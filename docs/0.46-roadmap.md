# Sandcastle 0.46 — roadmap

**Status:** planning → building
**Predecessor:** 0.45 "Leave the Room" (ACP client, effect ledger, gate enforcement, memory seam)
**Written:** 2026-08-25

---

## 1. The thesis

0.45 opened three doors and walked through none of them to the end:

- The gate now *enforces* — but the only judges it knows are one LLM prompt and
  a human. The design for a real outcome gate (`type: accept`) exists, is
  costed (~450-600 engine lines, no migration), and was a definition-of-done
  item that did not ship.
- Memory has a backend seam, a Protocol, and a closed traversal hole — but the
  only conformer is still mem0+Qdrant. The auditable markdown vault the seam
  was built for does not exist yet.
- The effect ledger makes resume safe — but nothing resumes. A crashed run is
  marked FAILED by `_recover_stuck_runs` (`worker.py:369-412`) and its ledger
  rows sit there proving work was done that nobody will ever continue.

0.46 ships no new category. It finishes what 0.45 started, because each of the
three is the missing half of something already sold:

> A gate that enforces deserves a judge worth obeying. A ledger that remembers
> deserves a worker that comes back. A seam deserves a second backend.

### 1. `type: accept` — the worker finished; did it succeed?

"The agent finished" and "the agent succeeded" are different facts, and the
engine records only the first. `accept` judges a target step's output against a
rubric — deterministic `checks:` first (free, `AssertionDef` reuse), then LLM
judges via the *gate* cost path (the eval-harness judge path is unusable:
returns bare text, fabricates 0.5 on error, cost discarded — proven in the
design doc). N-of-M quorum, human fallback through the existing approvals
surface, bounded re-work loop, and an **evidence pack** in the Black Box so the
verdict is auditable rather than a bare boolean.

Defaults keep cost visible: one judge, unanimous quorum, checks run first and
can reject for $0. On reject, `retryable=False` — same reasoning as the gate.

This lands *now* because 0.45 made it meaningful: an outcome gate on top of an
advisory gate would have been theatre.

### 2. The markdown vault

Memory an auditor can read. `INDEX.md` (≤1,500 tokens, enforced) plus domain
files, per-scope directories under the tenant, zero new dependencies — core
already carries pyyaml. Write policy: confirm ≥0.85 overlap, supersede
0.40-0.85, append below; TTL forgetting with a confirmations veto; flock +
`os.replace` + revision CAS for concurrency. Git-tracked, one commit per run
per scope, commit SHA pinned into the audit hash chain.

The design doc's honesty section ships as user-facing docs: six places keyword
retrieval is *worse* than vectors, named. The 120-domain cap is the price of
auditability, and the docs say so in those words.

Prerequisites already landed in 0.45: the Protocol, the wired setting, the
traversal fix, and the multiprocess concurrency test requirement.

### 3. Crash-resume

The ledger knows exactly which effects completed. The worker throws that away:
a crashed run goes to FAILED, full stop. 0.46 makes `_recover_stuck_runs`
requeue instead — the run re-executes from the top, the ledger memoizes the
completed prefix ($0, no duplicate sends), and in-flight claims past their
lease fail per `on_uncertain`, exactly as designed in 0.45.

Bounded: max N recovery attempts per run (a poison run must not requeue
forever), an opt-out setting, and FAILED stays the answer where the ledger is
unavailable. This is deliberately *replay-based* resume — no new scheduler
state machine; the ledger is the checkpoint.

## 4. Sequencing

```
1 (accept)        — executor.py, dag.py, routes.py
2 (vault)         — memory.py + new module; nearly disjoint
3 (crash-resume)  — worker.py + executor resume path
```

All three build in parallel worktrees off this branch. Landing order:
**3 → 1 → 2** (smallest blast radius first; accept and crash-resume both touch
executor.py, so the second to land reconciles).

## 5. Definition of done

1. `accept` rejects and approves end to end, evidence pack visible in the
   Black Box, re-work loop provably bounded, judge cost accounted via
   `_safe_cost` — with a test proving a rejected accept fails the run.
2. Vault: path-traversal test, **multiprocess** concurrency test, tenant
   isolation test, INDEX regeneration under overflow, and a run with
   `MEMORY_BACKEND=filesystem` completing with zero extra packages installed.
3. Crash-resume: kill a worker mid-run with a completed POST behind it;
   recovery re-runs the workflow; the POST fires **zero** more times; recovery
   attempts are bounded; ledger-unavailable still means FAILED.
4. Full suite green.
5. The measured claim, to be confirmed on a live run before quoting:
   > Kill the worker after step N of M. The run finishes anyway. Steps 1-N
   > cost $0 the second time and send nothing twice.
