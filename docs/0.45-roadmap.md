# Sandcastle 0.45 — "Bring Your Own Agent"

**Status:** planning
**Target:** 0.45.0
**Predecessor:** 0.44.0 "Keep the Ending" (context strategies)
**Written:** 2026-08-19

---

## 1. The thesis

0.44 worked because it was one idea with measured numbers behind it: when a
context goes over budget, *how* you shrink it decides whether the answer
survives. One idea, one line of config, real evidence.

0.45 takes the same shape. The idea:

> The agent harness is not the product. The loop around it is.

Sandcastle has four separate integrations of "run somebody else's agent loop and
collect the result": `delegate`, `openclaw`, `managed-agent` and `agent`. Each is
its own adapter, its own config block, its own failure modes, and each goes stale
independently when its vendor ships a new version.

The Agent Client Protocol (ACP) is a neutral socket for that shape. If Sandcastle
speaks ACP, then Claude Code, Codex, Goose and anything else with an ACP adapter
become workers **without a fifth adapter — and without a sixth one next quarter.**

### What ACP does *not* do (corrected after design review)

The first draft of this roadmap claimed ACP "is the generalization of all four."
That was overclaimed, and the design review disproved it. Verified:

| Existing type | Does ACP subsume it? |
|---|---|
| `openclaw` | **Yes**, design-wise — blocked only on OpenClaw shipping an adapter |
| `agent` (`runtime: local`) | **Upgrades it** — the local runtime is a non-streaming Ollama chat call |
| `managed-agent` | **No.** Container provisioning, memory stores and outcomes have no ACP vocabulary |
| `delegate` | **No.** It is Sandcastle-internal recursion into another workflow (`executor.py:6930`), not an external harness at all |

**One of four outright, not four of four.** The honest version of the pitch is not
"ACP replaces our adapters." It is: *ACP means we stop writing a new adapter for
every harness that appears*, plus two capabilities the existing integrations
**structurally cannot** offer — **graceful remote cancellation** and
**tool-call visibility while the external agent is still working.**

That is still the release. It is just a claim that survives contact with the code.

## 2. What ships

Four workstreams. One is the headline, one is load-bearing, two are supporting.

| # | Workstream | Role | Design doc |
|---|-----------|------|-----------|
| A | ACP client (`type: acp`) | Headline | `045/A-acp-design.md` |
| B | Replay that does not re-execute side effects | Load-bearing | `045/B-replay-idempotency-design.md` |
| C | Outcome gate (`type: accept`) | Supporting | `045/C-accept-gate-design.md` |
| D | Filesystem memory backend | Supporting | `045/D-filesystem-memory-design.md` |

### A. ACP client — the headline

Sandcastle becomes an ACP **client** in 0.45. It drives external agent harnesses;
it does not yet present itself as an ACP server.

**Correction from design review:** the first draft justified deferring server mode
by calling the spec "young and moving (~0.70)". That number is wrong. `0.70` is
the version of `@agentclientprotocol/claude-agent-acp`, the *adapter*. The ACP
**protocol version is the integer `1`**, and its schema is stable (v2 exists only
as an explicitly-gated unstable draft). Server mode is still deferred, but on
honest grounds: it is a separate surface with its own security model, and 0.45 is
already carrying a correctness fix that must land first.

Verified wire facts: stdio with newline-delimited JSON-RPC; `PromptResponse`
carries **only `stopReason`**, so the answer must be reassembled from
`agent_message_chunk` updates; permission option IDs are agent-defined, so we
match on `kind`, never on the id string.

**Cost accounting — state it plainly.** ACP v1 offers `usage_update{used, size,
cost?}`, and `used` is *context occupancy*, not consumption. Summing it is
meaningless. Rule: use the reported USD cost if the agent sends one (last wins),
never convert currency, never estimate. Consequence: **`max_cost_usd` is advisory
for `acp` steps, not enforced** — and the docs must say so rather than implying a
budget ceiling we cannot hold.

**Non-goals:** ACP server mode; ACP registry registration; deprecating any of the
four existing types. All four keep working.

### B. Replay that does not re-execute side effects — load-bearing

**The premise in the first draft was half wrong. The true half is worse.**

Disproved by design review, with proof lines:

- Checkpoints do **not** store only progress markers — `RunContext.snapshot()`
  persists the entire `step_outputs` dict (`executor.py:176-188`).
- A resumed run does **not** re-execute completed steps. `done_steps =
  set(skip_steps)` (`executor.py:9411`) and the skip set comes from the
  checkpoint's `step_outputs` keys. Skipping is entirely type-agnostic.
- Approval resume re-running completed siblings was **already fixed**, with a
  comment naming that exact bug at `executor.py:9515-9535`.

What is actually broken:

1. **The cassette memoizer is unreachable for 24 of 25 step types.** Cassette
   replay is wired inside `_execute_step_once` (`executor.py:2483`), but every
   type in `_HYBRID_STEP_TYPES` (`executor.py:1465`) — **including `llm` and
   `http`** — dispatches through `_execute_step_by_type` at `executor.py:1651`
   and never reaches it. `bundle.py:59` concedes this in one line:
   `REPLAY_SAFE_STEP_TYPES = frozenset({"standard"})`. So `sandcastle run
   --replay` **does** re-spend tokens and **does** re-POST. Independently found by
   two design agents; verified directly against the source.
2. **In-flight steps cancelled at a pause re-fire on resume** — they never wrote a
   `step_outputs` entry, so they are absent from `skip_steps`.
3. **Fan-out and loop have no sub-step checkpoint.** A 500-item HTTP fan-out that
   dies at item 499 re-POSTs all 500.
4. **There is no crash-resume at all.** `_recover_stuck_runs` marks crashed runs
   FAILED (`worker.py:369-412`).

**Design:** a durable **step effect ledger** with a write-ahead `in_flight` claim,
keyed on `sha256(effect_scope_id, tenant, step_id, parallel_index,
iteration_index, per-type effect fingerprint)`. A half-completed effect defaults
to **fail, not guess**. Memoized steps return `cost_usd=0.0`, matching the
existing precedent at `executor.py:2489`, so budget accounting comes out right for
free. An `Idempotency-Key` header on `http` is layered on as cheap extra defence,
with no pretence that it helps — most endpoints ignore it, and it never stops
provider billing.

**Migration:** head is `021`; the chain 001→021 was verified linear pair by pair.
New `022_step_effect_ledger.py` with `down_revision = "021"`. This repo has had a
three-way collision at `019` before, so: re-check the head immediately before
writing, keep it to a one-file commit, and add a `test_alembic_single_head` guard
so it cannot happen a fourth time.

**Non-goal:** a general durable-execution engine. This makes existing checkpoints
honest, not bigger.

### C. Outcome gate (`type: accept`) — supporting

The "cheap composition" thesis **held**: roughly 450-600 new engine lines and
**no DB migration**. `eval.check_assertion` (`eval.py:158`) is a pure async
function over a value, so it can score a step output mid-run with no new code —
`accept`'s `checks:` are literally `AssertionDef`.

Two findings changed the design:

- **The existing LLM-judge path is unusable.** `eval._check_llm_judge` →
  `autopilot._evaluate_llm_judge` → `generator._call_advisor_llm` returns **only
  text** (`generator.py:1319`); its cost is character-estimated into a side audit
  event and then discarded, it cannot take a per-judge model, and it fabricates a
  0.5 score on error (`autopilot.py:228`). Judges must use the *gate* path, which
  does account cost properly via `_safe_cost` (`executor.py:6575`).
- **`evals.py` is the wrong module** — it replays whole workflows against golden
  datasets (`evals.py:113`) and cannot run mid-run.

**A shipped gap this exposes, worth stating on its own:** `GateConfig` has exactly
one field, `strategies` (`dag.py:241`). A rejected gate returns
`status="completed"` with `output.decision = "rejected"` (`executor.py:6582`), and
**nothing in the engine consumes `decision`.** The strategies are evaluated
correctly — evaluation short-circuits on the first rejection, matching the
documented "ALL strategies must pass" (`site/llms-full.txt:74`) — but the verdict
has no enforcement path. A `gate` is advisory: unless the author manually wires a
`condition` on `{steps.gate.decision}`, a rejected gate stops nothing. For a
feature named "gate", that gap should be closed or documented, not left implicit.

Defaults chosen so cost stays visible: **one** judge, quorum **unanimous**,
`checks` run first and can reject for $0. The reject-retry loop is bounded four
ways (rounds ≤5, accept-local budget, run-budget projection, depth guard) plus two
validate-time structural bans. Judge critique is escaped before re-injection, or a
judge can inject templates. Landmine flagged: on reject the StepResult must set
`retryable=False` (`executor.py:78`), otherwise a step-level `retry:` silently
re-judges three times and can flip the verdict by luck.

### D. Filesystem memory backend — supporting

**This is bigger than the first draft assumed.** The central question was whether a
backend interface exists. It does not: memory is **hardcoded to mem0 + Qdrant**.
`_get_client` (`memory.py:165`) is a two-arm string switch and `client.add/search/
get_all/delete` are called directly at `:635, :640, :751, :789`. There is no
Protocol or ABC in `memory.py`.

The seam is pre-cut, though — every public function already takes a `backend: str`
parameter (`:619, :679, :783, :800, :880`) and a correct per-backend singleton
cache already exists (`:124, :192`). Extraction is mechanical. Sizing: **3-4 days**,
~180 LOC of refactor, ~700 LOC of new backend, ~700 LOC of tests.

Prerequisite discovered: **`settings.memory_backend` is dead config**
(`config.py:233`) — zero readers, all three executor call sites omit `backend=`,
and the repo's own audit already recorded this (`2026-05-31-audit-sweep.md:91`).
It has to be wired before any of this means anything.

**A live bug found on the way, which should be fixed regardless of this feature:**
`_VALID_SCOPE_RE` (`memory.py:147`) accepts `workflow:..`, `agent:..` and
`tenant:../workflow:x`, and the tenant sanitiser (`:336`) leaves `..` untouched.
Against Qdrant this is inert. Against a filesystem it is a path-traversal
primitive. Two independent defences are specified, plus a two-line upstream fix
that is worth landing on its own.

**The zero-dependency claim is real and quantified:** core resolves to 90
packages, core + the `memory` extra to 121. `pyyaml` is already core. So this is
genuinely memory with no vector database to operate.

Design: `INDEX.md` capped at **1,500 tokens**, measured with the repo's own
`estimate_tokens` (`compaction.py:65`) and enforced by regeneration plus row
dropping; hard caps of 120 domains per scope and 32 KB per domain file. Write
policy is deterministic keyword routing, then overlap ≥0.85 **confirm**, 0.40-0.85
**supersede**, <0.40 **append** — reusing the currently-dead `detect_conflicts`
(`memory.py:508`). Forgetting is TTL with a confirmations veto, in one end-of-run
pass. Concurrency is flock + `os.replace` + revision CAS; the concurrency test
must be **multiprocess**, because a threaded one can be GIL-serialised into a
false pass.

**Honesty requirement:** the design doc names six places keyword retrieval is
*worse* than vectors — no synonymy, no cross-lingual (the stopword list is
English-only, `memory.py:131`), lumpy Jaccard over ≤5 keywords, linear scan,
sticky routing errors, no graph. The 120-domain cap is not a limitation to hide;
it is the price of auditability, and the docs should say so in those words.

**Non-goal:** replacing the vector backend. Coexistence is a requirement.

## 3. What is deliberately excluded

Saying no is most of a roadmap. Each of these was considered and cut, with the
reason recorded so it can be revisited on evidence rather than on mood.

| Excluded | Why |
|---------|-----|
| **x402 / agentic payments** | Too early, and directly unsafe before workstream B lands — a replay that re-pays is a bug that costs real money. A BSL non-production licence plus an agent that spends is a support surface we do not want yet. |
| **MSCE (trace → skill crystallization)** | The paper is a month old with no implementations. Genuinely interesting; not shippable. |
| **`type: spawn`** | `sub_workflow` already exists. The delta is budget slicing and worktree isolation — that is configuration on an existing type, not a new type. |
| **Semantic cache** | In a workflow engine, "95% similar → serve the cached answer" is a mechanism for being quietly wrong. It is a benchmark feature, not a trust feature. If it ever ships: opt-in per step, never default, and never across tenants. |
| **`type: skill` (skills as runtime)** | Closer than it looks — `agent_skills.py` can already parse a `SKILL.md`. Deferred to 0.46 to keep 0.45 to one idea. The interesting half is not loading skills but *cutting* them, which is the same muscle as 0.44's context pruning and deserves its own release. |

### The step-type budget

Sandcastle has **25 step types**. The source material that prompted this
roadmap proposed five more across five releases. That is a feature-count
strategy, and feature count is not what made 0.44 land.

0.45 adds **two** (`acp`, `accept`) and retires none. Anything beyond that needs
to argue for itself against the alternative of making an existing type deeper.

### The unglamorous debt this does not address

Stated plainly so it is not mistaken for oversight. Five connectors — `teams`,
`mongodb`, `jira`, `snowflake`, `composio` — do not actually work.
`mcp_server.py` is still on mcp 1.x. `@cloudflare/sandbox` is pinned at 0.1.4.

Shipping a "new category" release while shipped connectors are broken is the
first thing a sceptical reader will find. This is not scheduled into 0.45, but
it should not survive 0.46 either.

## 4. Sequencing

```
B (replay idempotency) ──┐
                         ├──> C (accept gate)
A (ACP client) ──────────┘

D (filesystem memory) — independent, parallel
```

- **B before C.** An acceptance gate that can re-run its worker on resume is a
  gate that duplicates side effects. B is a precondition, not a nicety.
- **B before A, more strongly than first thought.** ACP is a hybrid step type,
  so it inherits the cassette gap on arrival: a brand-new step type that is
  invisible to the signed cassette and re-fires on replay. Landing B first means
  `acp` is born covered instead of being retrofitted.
- **D is fully independent** — different module, different tests.

Landing order into `main`: **B → A → C → D**, smallest blast radius first, each
as its own PR with its own tests.

## 5. Definition of done

0.45 does not ship until all of the following hold:

1. A worked example workflow driving a real external ACP agent end to end, in
   the repo, that a user can run.
2. A test that **proves** a replayed run does not fire an HTTP side effect
   twice, and that a memoized step does not re-charge the budget.
3. `type: accept` with an evidence pack visible in the Black Box, and a bounded
   answer to the reject-retry loop.
4. Filesystem memory with a path-traversal test and a concurrent-write test
   passing, and tenant isolation enforced.
5. Cost accounting honest for every new path, including the written admission
   that `max_cost_usd` is **advisory** for `acp` steps because ACP v1 reports
   context occupancy, not consumption.
6. Full test suite green (currently ~17.3k tests).

### The measured claim

0.44 shipped with numbers, and that is why it was believed. 0.45 needs its own
measurable claim rather than an adjective. Now that the design review has pinned
the actual defect, the claim can be stated precisely:

> Today, `sandcastle run --replay` re-executes `llm` and `http` steps, because
> cassette replay reaches exactly one of 25 step types. After 0.45: replay a
> workflow that spent *$X* and made *N* outbound calls, and the replayed run
> spends *$0* on the memoized prefix and makes *0* duplicate calls.

The test that backs it must run the **same workflow twice in one effect scope
without using `skip_steps`**, so it cannot pass by accident.

If that number is not reproducible, the release note says so instead.

## 6. Naming

0.44 was *Keep the Ending*. 0.45 is **"Leave the Room"**.

Two working names came before it, and the path between them is worth recording.

*Bring Your Own Agent* was chosen while this document still claimed ACP subsumed four
existing integrations. Design review disproved that - it subsumes one - so the name was
selling a claim we had ourselves refuted.

*Nothing Was Broken* replaced it, and described the work accurately: a gate that judged
and let everything through, a replay that re-sent your POST, a memory scope that
accepted `..`. But it named what **we** fixed rather than what the user gets, and a
release note written from that angle spends its best lines confessing instead of
selling.

*Leave the Room* names the outcome. Guard rails that hold, a replay that doesn't
re-send, and any harness you like behind your own gates all add up to one thing: you
can approve the rules once and stop watching. That is what a customer is buying, and
it is true of this release in a way it was not true of 0.44.

The internal record of what was broken stays in the changelog and the commit messages,
where it belongs. It does not have to be the headline.
