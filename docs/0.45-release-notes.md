# Sandcastle 0.45

## Approve it once. Then go do something else.

That's the whole promise of an agent. You decide what's allowed, you walk away, and
the work happens without you in the room.

0.45 is the release where you can actually leave the room.

---

## Your guard rails hold

A `gate` now stops the run.

Set the rule once — a compliance check, a spend limit, a quality bar, a second model
that has to agree — and a rejection ends it. No downstream step fires. No report gets
filed. The run comes back red, with the reason attached, and it stays red: a rejected
gate isn't retryable, because a judge you ask three times is a judge you're negotiating
with.

```yaml
- id: policy_gate
  type: gate
  gate_config:
    strategies:
      - type: llm_eval
        config: { prompt: "Approve only if every line item is within policy.", model: sonnet }
```

Not everything that rejects is a failure. A gate that filters — *no material deals
today*, *this email needs no action* — says so:

```yaml
    fail_on_reject: false
```

**What you get:** the difference between a system that judged and a system that
enforced.

## Run it again. Pay once.

Replay used to mean re-run. Now it means resume.

An effect ledger records what actually left the building — every outbound request,
every model call — keyed to the run's lineage. Come back an hour later, or after a
crash, or after an approval that sat overnight, and the work already done stays done.

> **Two full runs. One POST. $0 the second time.**

The invoice doesn't go out twice. The ticket isn't created twice. The tokens you
already spent aren't spent again, and your budget knows it — memoized steps bill zero
and still show you what the first run paid.

Opt a step out when you *want* it live:

```yaml
  replay: live
```

**What you get:** permission to retry. Most people never re-run a failed workflow
because they can't be sure what it'll do twice.

## Bring your own agent

`type: acp` — one socket, and the whole field plugs into it.

Claude Code. Codex. Gemini CLI. goose. Around thirty-eight harnesses speak the Agent
Client Protocol, and Sandcastle now speaks it too. Point a step at one and it becomes a
worker in your DAG, with your gates in front of it and your budget around it.

```yaml
- id: refactor
  type: acp
  acp_config:
    agent: claude
    cwd: /srv/checkouts/api
    message: "Refactor the request parser. Keep the tests green."
```

Two things you couldn't do before: **cancel a remote agent gracefully**, and **watch
its tool calls while it's still working** — you see what it's touching as it touches it,
not in a transcript afterwards.

It ships turned off. Name the directories an agent may work in, or the step doesn't
run:

```bash
SANDCASTLE_ACP_ALLOWED_ROOTS='["/srv/checkouts"]'
```

**What you get:** the model layer stops being a decision you're married to. The harness
is a config line now.

### Know what a turn costs

An `acp` turn carries the harness's whole system prompt. We measured a real one:

> **$0.27 for a one-word answer.**

Sandcastle bills what the harness reports, in its own currency, and never estimates.
Because ACP reports how *full* the context is rather than what you spent, use `timeout`
and `idle_timeout` as your hard limits on these steps.

## Memory you can point somewhere

Memory backends now sit behind one interface, selected by `MEMORY_BACKEND` — the seam
that a plain-markdown, git-diffable vault hangs off in 0.46. Scope validation was
hardened at the same time.

## Upgrading

Three things to check before you upgrade. All three take a minute.

**1. Gates that filter need one line.** If a gate in your workflow rejects as a matter
of course — a relevance check, a triage step, an "is there anything to do today" test —
add `fail_on_reject: false`. Gates that guard need nothing.

**2. Read a gate's verdict from the error.** A failed step publishes no output, so
`{steps.gate.decision}` is empty on a rejection. Branch on a verdict? Use
`fail_on_reject: false` and read the output as before.

**3. `MEMORY_BACKEND` is now honoured.** It was previously ignored. If you set it to
anything other than `local`, confirm that's what you want.

Migration `022` ships with this release and must run before your workers start.
