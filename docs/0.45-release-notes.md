# Sandcastle 0.45 — "Nothing Was Broken"

> **Draft.** Everything below is implemented and tested against the full suite
> (17,616 passing). One item remains open, listed at the end.

## Nothing was broken. That was the problem.

A gate that rejects and lets the work through isn't a gate. It's a formality.
It files the report anyway. It runs the payment anyway. And it tells you, in
writing, that everything completed.

We shipped 83 templates with gates in them. A sanctions screener. A payment
run. A discount approval. Not one of them could stop anything — the engine
judged, wrote down "rejected," and walked past its own guard rail. Zero of 83
ever read the verdict.

You didn't get a warning. You got a green check.

**This release is about the things that failed quietly.**

---

## The gate now stops the run

`fail_on_reject` defaults to true. A rejection fails the step, and it isn't
retryable — re-running a judge until it says yes turns a guard rail into a dice
roll.

Two of our own templates had been rejecting **100% of the time** and nobody
could tell, because rejection did nothing. Their prompts asked the judge for
"PASS." The engine was listening for "approved." We scanned all 116 judge
prompts. Those were the only two. They're fixed.

Not every gate is a guard. 32 of 88 are filters — "no material deals today" is a
Tuesday, not a failure. Those are marked, individually, with a stated reason.

## Replay stopped re-sending your POST

`--replay` re-spent tokens and re-sent requests. The memoizer was real, but it
lived on a code path that 24 of 25 step types never reach — `llm` and `http`
among them. One line in the source admitted it:
`REPLAY_SAFE_STEP_TYPES = frozenset({"standard"})`.

Now there's a durable effect ledger. The claim, and we tested it without the
shortcut that would have made it pass by accident:

> **Two full runs. One POST. $0 the second time.**

When the ledger can't be reached, the answer follows the deployment instead of a
flag. Your laptop has no database, so it runs and warns. A server does, so it
stops. The safe default is the one most people actually run.

## A memory scope could contain `..`

`workflow:..`, `agent:..`, `tenant:../workflow:x` — all accepted. Harmless
against a vector store. A path-traversal primitive the moment anything writes to
disk. The pattern also ended in `$`, so a trailing newline slipped through.

Fixed, with the backend seam that makes the next release's markdown vault
possible.

## Bring your own agent

We wrote the same thing four times.

`delegate`. `openclaw`. `managed-agent`. `agent`. Four adapters for one idea — run
somebody else's agent loop, collect the result. Each with its own config, its own
failure modes, its own way of going stale the week its vendor ships a new version.

The fifth one was already coming. There are around thirty-eight harnesses that speak
the Agent Client Protocol now. We were going to write an adapter for every one of
them that mattered, forever.

`type: acp` ends that. One socket. Claude Code, Codex, Gemini CLI, goose — they plug
in, and the next one plugs in without us.

**Now the part where we tell you what it doesn't do.**

We said this replaces all four adapters. It doesn't. It replaces `openclaw`, and it
upgrades `agent`'s local runtime. It cannot replace `managed-agent` — container
provisioning has no vocabulary in ACP — and it cannot replace `delegate`, which was
never an external harness at all, just Sandcastle calling itself.

One of four. We'd rather say that than have you find it.

What you get beyond the socket is the thing the old adapters structurally could not
do: **cancel a remote agent gracefully, and watch its tool calls while it's still
working.**

Client only. Sandcastle drives harnesses; it doesn't present itself as one yet — that's
a separate surface with its own security model, and it isn't this release.

**It ships turned off.** `acp_allowed_roots` is empty by default. Spawning somebody
else's agent with write access to "any directory on this box" is not a defensible
default, so you name the directories or the step type doesn't run.

### About the money

An `acp` turn costs more than you think. We measured one:

> **$0.27. For a one-word answer.**

Every turn carries the harness's entire system prompt. Budget accordingly.

We also confirmed, against a live `claude-agent-acp` 0.70.0, that it reports its own
cost in USD — so we bill what it tells us. We never estimate. ACP reports `used`, and
`used` is how full the context is, not what you spent: 28,585 tokens of a million-token
window were occupied to answer with one word. Turning that into a bill would be making
up a number.

Which means: **`max_cost_usd` is advisory for `acp` steps.** The field is optional in
the spec, and one harness reporting cost is not all of them. `timeout` and
`idle_timeout` are the real limits. We'd rather tell you the ceiling doesn't hold than
let you believe it does.

### It found a bug in our own ledger

`acp` steps carry no prompt, so their effect fingerprint came out of the step type and
the default model — identical for every `acp` step in a workflow.

Which meant the new replay ledger would have memoized one agent's turn and handed the
transcript to a different one. "Refactor the parser in /repo/alpha" and "delete
everything in /repo/beta" hashed to the same value.

Two features that each work alone, broken where they meet. Fixed, and pinned by a test.

## Breaking

Read this part.

- **A gate that rejects now fails the run.** Using one as a filter? Set
  `fail_on_reject: false`.
- **A failed step publishes no output.** The verdict is in `.error`, not
  `{steps.gate.decision}`.
- **`MEMORY_BACKEND=cloud` used to silently give you `local`.** Now it errors.
  Loud is better.

## Not in this release

Crash-resume. Fan-out sub-step checkpoints. `classify` stays outside the ledger —
memoizing it would silently un-skip the wrong branch.

Five connectors still don't work. That isn't fixed here, and it shouldn't
survive 0.46.
