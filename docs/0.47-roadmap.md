# Sandcastle 0.47 — roadmap

**Status:** planning → building
**Predecessor:** 0.46 (accept, filesystem vault, crash-resume) — **unreleased**, as is 0.45
**Written:** 2026-08-26
**Source:** X research refresh of 2026-08-25 (`sandcastle-top10-x-ai-v2.txt`), scored
against the actual tree: four of its ten items were already built on the
unreleased branches. What remains actionable is below.

---

## 1. The thesis

> Memory you can store is a log. Memory you can grade is memory.
> An output you can claim is a report. An output you can verify happened is work.

0.46 gave memory a readable form (the vault) and gave outcomes a judge
(`accept`). 0.47 closes the two loops those opened:

- The vault records confirmations, TTL, supersede history and an attic — the
  exact metadata a staleness/forgetting score needs. Nothing computes it yet.
  A memory store that never says "3 of these 10 memories are stale" is, per
  the 330-day ops report circulating on X, "a log with good manners."
- `accept` judges what a step *returned*. Nothing checks that what a run
  *claimed* actually happened — the worst failure in that same 330-day report
  is **silent success**: "1 reply created," never sent. We shipped a release
  about silent failures; this is the third member of the series (the gate
  that didn't enforce, the replay that re-sent, the output that never
  happened).
- Both new step types (`acp`, `accept`) exist with zero templates showing
  them off, while the a16z data says the fastest-growing agent use is
  knowledge work outside code (legal 108×, sales 41×, recruiting 41×).

## 2. What ships

| # | Workstream | Builds on |
|---|-----------|-----------|
| 1 | `sandcastle memory eval` — staleness & forgetting scoring | 0.46 vault metadata |
| 2 | Silent-success detector | audit chain, RunStep outputs, notify/effect records |
| 3 | Knowledge-work template pack | `accept` + `acp` step types |

### 1. Memory eval — grade the store, not just the retrieval

A CLI (`sandcastle memory eval`) and library that scores a memory scope:
staleness (age vs TTL vs confirmations), forgetting health (does the store
ever shrink; attic/tombstone throughput), contradiction pressure (supersede
chains), and retrieval sanity (does a query for X surface the *current* X or
a superseded one). Works best on the filesystem vault, where the metadata is
first-class; degrades honestly on mem0 (say what cannot be measured there
rather than faking it).

### 2. Silent-success detector

A sweep that cross-checks claimed outputs against evidence: a `notify` step
that reports delivery must have a delivery record; an `http` step that claims
a 2xx write must have the effect-ledger row; a run that "completed" with
side-effecting steps must have matching audit events. Flag, don't guess:
the deliverable is a report of runs whose claims lack evidence after N hours,
surfaced via CLI and an API endpoint — not an auto-repair.

### 3. Knowledge-work template pack

Templates that exercise what 0.45/0.46 built, aimed at the demand curve:
contract review (`accept` judging extraction against a rubric), CRM enrich,
recruiting screen. ACP worker as the executor where it fits. Registry and
site counts must be regenerated by the scripts, never edited by hand.

## 4. Sequencing

All three streams are nearly disjoint (1: new module + CLI; 2: sweep + CLI +
routes; 3: templates + registry). Parallel worktrees; landing order by blast
radius: **2 → 1 → 3**.

Design notes are written into `docs/design/047-*.md` by each implementer as
part of the deliverable — in the repo, not the scratchpad, per the 0.46
lesson.

## 5. Definition of done

1. `sandcastle memory eval <scope>` produces a graded report on a real vault,
   with at least staleness, forgetting and contradiction scores, and an
   honest "not measurable on mem0" section.
2. The silent-success sweep, run against a seeded database containing one
   genuinely silent run, finds exactly it — no false positive on an honest
   run, no false negative on the seeded one.
3. Each pack template validates, passes hub validation, and at least the
   contract-review template runs end to end with a real `accept` verdict.
4. Registry/site counts regenerated by script and consistent everywhere.
5. Full suite green.

## 6. Release debt (standing, not this release's scope)

0.45 "Leave the Room" and 0.46 are both unreleased. Every roadmap since has
built on an unreleased branch. The one-vs-two-release decision is open with
the owner; the v2 X research ("nothing new has appeared on the site") is an
argument for releasing soon and once.
